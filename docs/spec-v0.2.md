# 글만 — 스펙 v0.2

> 한 줄 정의: **hwp·docs 문서를 열고, 텍스트만 읽고 고치고, 원본 형식으로 저장해서 돌려보내는 얇은 에디터.**

- 상태: v0.2 — 이름·플랫폼·속성 정책 확정 (2026-10-31)
- 설계 방향: 단일 창, 리본/숨긴 메뉴 없음, 액센트 최소화 (승인된 UI 스케치 기준)
- 대상 사용자: 텍스트 round-trip이 전부인 작업 흐름(저자 최의택). 시선 기반 입력 환경 고려.
- 협업 전제: 출판사 등 상대방과의 문서 교환이 일상적이라 **원본 보존은 편의가 아닌 하드 요구사항**.

---

## 1. 목표 / 비목표

### 목표
- `.hwp` · `.hwpx` · `.docx` 파일을 **외부 앱 없이** 열어 텍스트를 읽고 편집한다.
- 저장 시 **원본 형식 그대로** 다시 만든다 (한컴오피스·MS Word에서 바로 열림).
- 텍스트 이외의 문서 내용(서식, 표, 그림, 코멘트, 변경 사항 추적)을 **손대지 않는다**.

### 비목표 (v1에서 하지 않음)
- 전체 기능 워드프로세서 (리본, 스타일 편집기, 표 편집, 수식 입력 등)
- `.doc` 레거시 바이너리 지원 (필요 시 별도 변환 경로로만, v2 후보)
- HWP 3.x 이하 구형 포맷
- 암호화 문서(비밀번호 걸린 것, 배포용/복사 방지) 편집 — 탐지해서 명확히 거부만
- 실시간 협업, 클라우드 동기화
- PDF 내보내기 (원하는 사람이 있으면 OS 인쇄로 충분)

## 2. 지원 형식 범위

| 형식 | 구조 | 읽기 | 쓰기(원본 포맷 저장) | 비고 |
|---|---|---|---|---|
| `.hwp` (5.x) | CFB(OLE2) 바이너리 | ✅ | ✅ | 한컴 스펙 공식 공개. 레코드 보존이 핵심 |
| `.hwpx` (HWPX) | ZIP + OWPML XML | ✅ | ✅ | `Contents/Body/SectionN.xml`의 `<hp:t>`만 교체하는 in-place 패치 경로 우선 |
| `.docx` | ZIP + OOXML | ✅ | ✅ | `word/document.xml`의 `<w:t>`만 교체하는 in-place 패치 (papyrus-docx가 검증한 방식) |
| `.doc` | OLE2 바이너리 | ❌ | ❌ | v1 범위 밖 |

## 3. 핵심 워크플로

```
열기 → 읽기(전체 텍스트 + 구조) → 텍스트 편집 → 저장(원본 형식) → (앱 밖에서) 보내기
```

- **열기**: 파일 드롭, 최근 문서 목록, OS 파일 선택. 형식은 자동 감지.
- **읽기**: 본문 텍스트를 페이지 흐름대로 표시. 표 안 텍스트도 포함.
  - 서식(굵기·색 등)은 *가볍게* 반영하되 편집 대상이 아니므로 과장하지 않음.
- **편집**: 텍스트 치환·삽입·삭제만. 찾기/바꾸기는 필수(대량 수정의 90%).
- **저장**: 원본 형식으로 저장. 저장마다 "보존 보장" 확인 문구 표시.
- **보내기**: 앱이 대신 보내지 않음. 저장된 파일을 OS 공유로 넘기는 것까지가 범위.

---

## 4. 보존 계약 (Fidelity Contract) — 이 앱의 존재 이유

저장 후 원본 파일과 비교했을 때 **사용자가 바꾼 텍스트만 다르고, 나머지는 동일**해야 한다.

| 항목 | 보장 수준 |
|---|---|
| 서식(글자, 크기, 줄 간격, 여백) | 보존 — 손대지 않음 |
| 표 구조·셀 내용(미편집 셀) | 보존 |
| 그림·차트·수식·OLE 객체 | 보존 — 바이트 그대로 |
| **코멘트** | 보존 (`.hwp`: Comment 스트림, `.docx`: `word/comments.xml`) |
| **변경 사항 추적** | 보존 (`.docx`: `w:ins`/`w:del`, `.hwp`: 변경 레코드) |
| 문서 속성(제목, 작성자, 날짜) | 보존. 수정일만 갱신하는지 여부 → open question |

**검증 기준**: §8의 round-trip 테스트가 이 계약의 자동 검증이다.

## 5. 아키텍처와 엔진 선택

```
┌─────────────────────────────┐
│  얇은 UI (단일 창)           │
├─────────────────────────────┤
│  문서 모델 (텍스트 + 위치 좌표) │
├─────────────────────────────┤
│  HWP/HWPX 엔진    │ docx 엔진 │
│  python-hwpx      │ zip+lxml  │
└─────────────────────────────┘
```

### 엔진 후보와 추천

| 용도 | 1순위 (추천) | 대안 | 근거 |
|---|---|---|---|
| `.hwp`/`.hwpx` 읽기·쓰기 | **python-hwpx** (순수 Python, 한컴 불필요, 코멘트·각주·변경 추적 명시 지원) | hwp-cli (Rust, `edit`가 미해석 레코드 보존 명시 — 신뢰 비교용) | Python 단일 스택 유지. hwp-cli는 원거리(fidelity) 대조 검증 도구로 병행 활용 |
| `.docx` 읽기·쓰기 | **zip + lxml in-place 패치** (미이해 엘리먼트는 그대로, `<w:t>`만 교체) | papyrus-docx (브라우저 전용이라 데스크톱에는 부적합하지만 설계 검증 참고) | ECMA-376 공개 스펙. rsid·paraId 속성 보존 필수 |

### 앱 기술 스택
- **플랫폼: Windows 전용** (맥 고려 안 함 — 테스트 환경 부재 + macOS는 아름다운 앱이 이미 많음)
- **추천: WinUI 3 (.NET/C#)** — Windows 11 네이티브 디자인(Mica, Fluent 2, 라운지드 코너)을 쓸 수 있는 유일한 경로.
  - `.docx` 엔진: C# 직접 구현 (zip + `document.xml` in-place 패치 — 사이드카 불필요)
  - `.hwp`/`.hwpx` 엔진: **Python 사이드카** (python-hwpx, PyInstaller로 번들링)
- 배제: PySide6(디자인 근사만 가능), Tauri(이중 스택), Flutter(생태계 불일치), Electron(무게)

## 6. UI/UX 스펙 (승인된 스케치 기준)

### 상태 3개
1. **처음**: 드롭존 + 최근 문서 목록. "원본 형식으로 읽고, 원본 형식으로 저장합니다" 문구.
2. **편집**: 상단 바(파일명 + 형식 배지 + 자 수), 본문 열(명조, ~68ch), 하단 바("변경됨 · N줄 수정" + 내보내기/저장 버튼).
3. **저장 후**: 토스트 "원본 형식으로 저장했습니다 — 서식·코멘트·변경 사항 보존됨".

### 토큰
- 색: 종이 `#F7F7F5`, 잉크 `#16181D`, 헤어라인 `#E4E4E0`, 액센트 `#3457D5`(저장 버튼·체크만), 선택 강조 옅은 노랑
- 글자: UI = Pretendard(산세리프), 본문 = Noto Serif KR(명조)
- 모션: 없음. 액션에 대한 응답(토스트, 포커스)만

### 접근성 (시선 입력 환경)
- 숨긴 메뉴(⋯/우클릭) 없음 — 모든 액션은 항상 보이는 버튼으로 노출
- 최소 타깃 42px 이상, 두꺼운 포커스 링
- 호버에 의존하는 기능 없음
- 키보드/시선 순환 가능한 단일 포커스 흐름

## 7. 에러 처리 원칙

| 상황 | 행동 |
|---|---|
| 암호화/배포용 문서 | "이 문서는 복사 방지(또는 비밀번호)가 걸려 있어 열 수 없습니다" — 이유 + 대안(한컴오피스) 안내 |
| 미지 레코드/엘리먼트 발견 | 저장은 가능하나 토스트에 "미확인 구조 N건 보존됨" 명시 → 사용자 판단에 맡김 |
| 저장 실패 | 원본 파일 절대 건드리지 않음. 새 파일로만 쓰되 실패 시 원본 무결성 확인 후 보고 |

## 8. 검증 전략 (신뢰의 핵심)

1. **round-trip 자동 테스트**: 문서를 열기 → 아무것도 안 고치고 저장 → 원본과 diff
   - `.docx`: zip 내 각 파일 바이트 비교 (미편집 문서 = byte-identical 목표)
   - `.hwp`: hwp-cli `dump`로 레코드 트리 대조 (byte 동일은 어려울 수 있으므로 의미 보존 기준)
2. **편집 round-trip**: 텍스트 N개만 수정 → 저장 → (a) 수정 부분만 diff에 나타남, (b) 코멘트·변경 추적 개수 불변 확인
3. **코퍼스**: 실제 문서 10~20부(정부 양식, 소설 원고, 표 많은 보고서, 그림 포함 문서)를 fixtures로 유지
4. **수동 검증 게이트**: 릴리스 전 사용자가 한컴오피스·MS Word에서 직접 열어 확인 — 확인 전 배포 없음 (사용자 원칙)

## 10. 리스크와 open questions

1. **`.hwp` byte-identical 저장** — python-hwpx가 모든 레코드를 원본 바이트로 복원하는지 문서마다 다를 수 있음. hwp-cli 대조 + "미확인 구조 보존" 알림으로 완화. (M2에서 실측)
2. **텍스트 길이 변화와 페이지 배치** — HWP의 줄 캐시(line cache) 때문에 일부 뷰어가 낡은 레이아웃을 볼 수 있음. 저장 시 한컴과 같은 값으로 재계산하는지 python-hwpx 지원 여부 확인 필요.
3. **기술 스택** — ✅ 맥 배제 → Windows 전용 결정. WinUI 3 + Python 사이드카 추천 (최종 승인 대기).
4. **앱 이름** — ✅ 결정: **글만**. "다 버리고 텍스트만"을 이름으로.
5. **문서 속성(수정일) 갱신** — ✅ 결정: 수정일은 갱신, 원본 생성일은 보존. (협업 전제 문서 교환에서 원본 정체성 유지가 핵심)
